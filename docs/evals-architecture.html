Architecture at a glance

The harness is end-to-end at the application boundary: Promptfoo supplies a case, the custom provider calls the same production translation function used by Raycast, and the resulting app-level projection is graded twice.

Layered suite design

The normal workflow favors risk-based depth. Complete pair breadth is available separately because every row invokes both a candidate model and a judge.

12 Smoke Fixed multilingual sample across Latin, Cyrillic, and CJK scripts. ≈ 24 model calls
96 Standard Routine risk-based regression suite, including the 12 smoke rows. ≈ 192 model calls
272 Matrix One common-word probe for every one of the 17 × 16 directed pairs. ≈ 544 model calls
368 All Standard depth and complete pair breadth in one deliberately expensive run. ≈ 736 model calls
Standard coverage

32 English-pivot directions

Every non-English language has at least two cases to English and two from English. English↔Ukrainian receives deeper coverage because it is the default and historically highest-risk pair.

Matrix coverage

All 272 directed pairs

Each language’s standard word for “water” is translated into all 16 other languages. This tests pair viability and language purity, not deep semantic competence.

What each grader owns

The separation prevents an LLM judge from deciding facts that code can determine exactly, while avoiding brittle exact-match scoring for legitimate linguistic variation.

Deterministic

application_contract

  • Exact input and language-pair preservation
  • Expected success or application error code
  • One to five complete senses
  • Unique translation + part-of-speech identities
  • Expected correction, with no spurious correction
  • Exact source form in each source-language example
  • Absence of explicit known-wrong forms
Model-graded

translation_quality

  • Semantic accuracy and required sense coverage
  • No false friends, literal idioms, or invented senses
  • Natural target grammar, spelling, morphology, and register
  • Language purity rather than neighboring-language drift
  • Source/target example fidelity
  • Learner-useful sense ordering and part of speech
About “Provider output is not valid JSON”

This is a harness-boundary diagnostic, not a test of Gemini’s structured output. Invalid model JSON is rejected earlier by production parsing and Zod validation. The assertion parses the provider’s serialized app projection because Promptfoo supplies custom assertions with a string.

Error routing is part of the architecture

The provider deliberately distinguishes deterministic application outcomes from infrastructure failures so the eval never grades transport problems as translations.

Outcome domain

Projected and graded

Errors such as word-not-found and invalid-word-input become an app-level JSON result with status: error. Contract cases can assert the exact expected verdict.

Infrastructure

Surfaced as provider errors

Network failures, invalid credentials, model availability, malformed model responses, and other infrastructure causes return Promptfoo provider errors. Assertions do not run against a misleading synthetic translation.

Responsibility by file

The architecture is split into small surfaces so dataset evolution, production behavior, exact contracts, linguistic policy, and reporting can change independently.

File Responsibility Key boundary
evals/promptfooconfig.yaml Promptfoo orchestration, judge rubric, provider, filters, concurrency, and threshold. One source of truth for suite-wide execution policy.
evals/promptfoo/cases.cjs Generates the 96 standard and 272 matrix cases with metadata. Dataset breadth, difficulty, category, intent, and exact expectations.
evals/promptfoo/provider.ts Validates Promptfoo inputs and calls production translateWord. Adapter between eval runner and application behavior.
src/lib/gemini.ts Production prompt, Gemini request, structured validation, outcome routing, and deduplication. The actual behavior under evaluation.
evals/promptfoo/assert-output.cjs Deterministic application-contract grading with component reasons. Exact facts, never subjective language quality.
evals/promptfoo/judge-prompt.txt Injection-resistant judge wrapper and binary output contract. Candidate output and case data are untrusted.
evals/promptfoo/transform-vars.cjs Serializes per-case expectations for the rubric. Stable handoff from structured vars to prompt text.
evals/promptfoo/report.ts Turns Promptfoo JSON into grouped Markdown summaries. Redacts likely credentials from recorded failure reasons.
evals/promptfoo/suite.test.ts Enforces counts, IDs, language registry agreement, pair coverage, scripts, and valid inputs. Prevents silent dataset drift.

How to run each layer

Use the smallest layer that answers the current question. All commands use the same production provider and grading policy. 

# Configuration only; no Gemini calls
npm run eval:validate

# Fast, fixed developer signal
npm run eval:smoke

# Routine 96-case risk-based regression run
npm run eval

# Complete 272-pair breadth run
npm run eval:matrix

# Standard + matrix, 368 cases
npm run eval:all

# Regenerate Markdown from the latest standard JSON result
npm run eval:report

# Open the local Promptfoo viewer
npm run eval:results
Result artifacts

Promptfoo JSON and generated Markdown summaries live under evals/results/. The report groups pass rate, failures, and provider errors by language pair, category, difficulty, and tier.

What this architecture does not prove

Broad automated coverage is useful evidence, not a substitute for calibrated judges and native-speaker review.

The 75% gate is intentionally permissive
A standard run can have 24 unsuccessful rows and still clear the aggregate threshold. Review every zero-pass pair and every subgroup below 75%; do not treat the top-line gate as release approval.
The all-pairs matrix is shallow
“Water” establishes basic pair viability and catches language-routing problems. It does not establish idiom, morphology, register, or polysemy quality for every pair.
The judge still needs human calibration
The semantic rubric should be compared against human-labeled development and holdout examples, with native-speaker review for the supported languages. Product tier alone does not prove judge reliability.
Text translation is a separate future harness
These evals target words and short vocabulary expressions through translateWord. The app’s translateText path has different output contracts and should use its own provider and dataset.
